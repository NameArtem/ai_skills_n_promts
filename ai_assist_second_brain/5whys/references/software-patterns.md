# Типичные паттерны первопричин в ПО

Часто встречающиеся первопричины при применении 5-Whys к проблемам в программном обеспечении.

---

## Паттерн 1: Отсутствие обработки ошибок

### Типичная цепочка
```
Проблема: Сервис периодически возвращает ошибку 500
Why 1: Необработанное исключение в обработке платежей
Why 2: Внешний API вернул неожиданный формат
Why 3: Версия API изменилась без предупреждения
Why 4: Нет валидации схемы ответа API
Why 5: Обработка ошибок предполагает только счастливый путь
```

### Тип первопричины
**Пробел в проектировании** — оборонительное программирование не применено

### Контрмеры
| Тип | Действие |
|----------|----------|
| Немедленно | Добавить try-catch, возвращать корректную ошибку |
| Профилактика | Валидация схемы всех внешних входных данных |
| Обнаружение | Оповещение о неожиданных форматах ответа |

---

## Паттерн 2: Утечки ресурсов

### Типичная цепочка
```
Проблема: Память приложения растёт вплоть до OOM
Why 1: Использование heap растёт со временем
Why 2: Объекты не собираются сборщиком мусора
Why 3: Ссылки удерживаются в статическом кэше
Why 4: У кэша нет политики вытеснения
Why 5: Кэш спроектирован под маленькие данные, а теперь они большие
```

### Тип первопричины
**Неверное допущение о масштабировании** — проект не учитывал рост

### Контрмеры
| Тип | Действие |
|----------|----------|
| Немедленно | Перезапустить сервис, добавить память |
| Профилактика | LRU-кэш с ограничениями по размеру |
| Обнаружение | Оповещения об использовании памяти на 80% |

## Паттерн 3: Гонки (race conditions)

### Типичная цепочка
```
Проблема: Иногда создаются дубликаты заказов
Why 1: Один и тот же заказ вставлен дважды
Why 2: Два запроса обработаны одновременно
Why 3: Нет проверки ключа идемпотентности
Why 4: Предполагался один запрос на заказ
Why 5: В проектировании нет мышления в терминах распределённых систем
```

### Тип первопричины
**Пробел в конкурентности** — допущения однопоточной модели в распределённой системе

### Контрмеры
| Тип | Действие |
|----------|----------|
| Немедленно | Уникальное ограничение в БД |
| Профилактика | Обязательные ключи идемпотентности |
| Обнаружение | Обнаружение дубликатов в мониторинге |

---

## Паттерн 4: Дрейф конфигурации

### Типичная цепочка
```
Проблема: Фича работает в staging, но падает в проде
Why 1: В проде отсутствует переменная окружения
Why 2: Ручной деплой пропустил переменную
Why 3: Нет валидации конфигурации при старте
Why 4: Нет infrastructure-as-code для переменных окружения
Why 5: Управление конфигурацией рассматривалось как второстепенное
```

### Тип первопричины
**Пробел в процессе** — ручной процесс там, где нужна автоматизация

### Контрмеры
| Тип | Действие |
|----------|----------|
| Немедленно | Добавить недостающую конфигурацию |
| Профилактика | IaC для всей конфигурации |
| Обнаружение | Проверка различий конфигурации в CI/CD |

---

## Паттерн 5: Каскадные отказы

### Типичная цепочка
```
Проблема: Все сервисы лежат во время всплеска трафика
Why 1: Пул соединений с БД исчерпан
Why 2: Запросы выполняются в 10 раз дольше обычного
Why 3: Отсутствует индекс для нового паттерна запросов
Why 4: Новая фича добавила запрос без ревью
Why 5: В процессе PR нет ревью производительности запросов
```

### Тип первопричины
**Пробел в процессе** — отсутствует шаг ревью

### Контрмеры
| Тип | Действие |
|----------|----------|
| Немедленно | Добавить индекс, перезапустить сервисы |
| Профилактика | Чек-лист ревью запросов в PR |
| Обнаружение | Оповещения о задержках запросов |

---

## Паттерн 6: Уязвимости безопасности

### Типичная цепочка
```
Проблема: В проде обнаружена SQL-инъекция
Why 1: Пользовательский ввод попадает прямо в SQL-запрос
Why 2: Для запросов используется конкатенация строк
Why 3: Разработчик не знал о параметризованных запросах
Why 4: Нет обучения безопасности для новых разработчиков
Why 5: Безопасность не входит в процесс онбординга
```

### Тип первопричины
**Пробел в знаниях** — недостаток обучения/онбординга

### Контрмеры
| Тип | Действие |
|----------|----------|
| Немедленно | Исправить запрос, провести аудит похожего кода |
| Профилактика | Обязательное обучение безопасности |
| Обнаружение | Статический анализ в CI |

---

## Паттерн 7: Отказы зависимостей

### Типичная цепочка
```
Проблема: Сборка упала после выходных
Why 1: npm install не работает
Why 2: Версия пакета больше не существует
Why 3: Используется плавающая версия (^1.0.0)
Why 4: Lock-файл не закоммичен
Why 5: Нет политики фиксации версий зависимостей
```

### Тип первопричины
**Пробел в политике** — отсутствует стандарт/регламент

### Контрмеры
| Тип | Действие |
|----------|----------|
| Немедленно | Зафиксировать версию, закоммитить lock-файл |
| Профилактика | Требовать lock-файлы во всех репозиториях |
| Обнаружение | CI падает, если lock-файл отсутствует |

---

## Паттерн 8: Повреждение данных

### Типичная цепочка
```
Проблема: Пользователи видят неверный баланс счёта
Why 1: Расчёт баланса включает удалённые транзакции
Why 2: Мягкое удаление не отфильтровано в запросе
Why 3: Новый запрос скопирован со старого без фильтра
Why 4: Нет стандартных паттернов запросов/слоя репозитория
Why 5: Каждая фича пишет сырые SQL независимо
```

### Тип первопричины
**Пробел в архитектуре** — отсутствует слой абстракции

### Контрмеры
| Тип | Действие |
|----------|----------|
| Немедленно | Исправить запрос, провести аудит похожих |
| Профилактика | Паттерн repository со стандартными фильтрами |
| Обнаружение | Проверки согласованности данных |

## Сводка категорий первопричин

| Категория | Описание | Типичное исправление |
|-----------|----------|----------------------|
| **Пробел в проектировании** | Отсутствие учёта в проектировании | Перепроектировать компонент |
| **Пробел в процессе** | Ручной труд там, где нужна автоматизация | Автоматизировать процесс |
| **Пробел в знаниях** | У команды нет навыка/осведомлённости | Обучение, документация |
| **Пробел в политике** | Нет стандарта/регламента | Создать и внедрить политику |
| **Пробел в архитектуре** | Отсутствует абстракция/паттерн | Рефакторинг архитектуры |
| **Неверное допущение о масштабировании** | Проект не предусматривал рост | Перепроектировать под масштаб |
| **Пробел в конкурентности** | Однопоточное мышление в распределённой системе | Добавить синхронизацию |

## Анти-паттерны в 5-Whys

### Анти-паттерн 1: Игра в обвинения
```
❌ Неправильно:
Why 5: Разработчик плохо протестировал

✓ Правильно:
Why 5: Нет автоматического покрытия тестами этого сценария
```

### Анти-паттерн 2: Отговорка про вендора
```
❌ Неправильно:
Why 5: API третьей стороны ненадёжен

✓ Правильно:
Why 5: Нет повторов/фолбэка для внешних зависимостей
```

### Анти-паттерн 3: Отговорка про ресурсы
```
❌ Неправильно:
Why 5: У нас нет времени сделать это правильно

✓ Правильно:
Why 5: Технический долг не приоритизирован в планировании
```

### Анти-паттерн 4: Отговорка про сложность
```
❌ Неправильно:
Why 5: Система слишком сложная

✓ Правильно:
Why 5: Нет документации/тестов для сложных взаимодействий
```

```markdown

- **Симптом:** [Что видели пользователи/мониторинг]
- **Время:** [Когда обнаружено]
- **Длительность:** [Как долго]
- **Влияние:** [Затронутые пользователи/выручка]

### Анализ

| Почему | Вопрос | Ответ | Доказательства |
|--------|--------|-------|----------------|
| 1 | Почему произошло [симптом]? | | Логи/метрики |
| 2 | Почему произошло [Why 1]? | | Код/конфигурация |
| 3 | Почему произошло [Why 2]? | | История/коммиты |
| 4 | Почему произошло [Why 3]? | | Процесс/документы |
| 5 | Почему произошло [Why 4]? | | Политика/культура |

### Первопричина
- **Категория:** [Проектирование/Процесс/Знания/Политика/Архитектура]
- **Формулировка:** [Одно предложение]

### Действия
| Приоритет | Действие | Ответственный | Статус |
|-----------|----------|---------------|--------|
| P0 | [Немедленное исправление] | | |
| P1 | [Профилактика] | | |
| P2 | [Обнаружение] | | |
```
