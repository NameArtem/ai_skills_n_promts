# Lean Analytics

## О методологии

**Lean Analytics** — подход, сочетающий принципы Lean (бережливого производства) с аналитикой. Используется стартапами и малым бизнесом для поиска, измерения и масштабирования бизнес-моделей: фокус на ценности для клиента, устранение потерь, постоянное улучшение на основе данных.

### Ключевые характеристики

- **Цель:** эффективность и устранение потерь, рост на основе измерений.
- **Этапы/принципы:** фокус на ценности для клиента, устранение потерь, постоянное улучшение, One Metric That Matters (OMTM).
- **Применение:** стартапы, малый бизнес, запуск и оптимизация продуктов.
- **Преимущества:** быстрые циклы обучения, подходит для MVP, экономия ресурсов, рост через данные.
- **Недостатки:** требует глубокого понимания бизнеса, не подходит для сложных аналитических задач, легко выбрать неверные метрики (vanity metrics).

## Ключевые принципы

1. **Ценность для клиента.** Каждый шаг должен создавать ценность; всё, что не создаёт — потеря (waste).
2. **Устранение потерь.** Сократить лишнюю работу, лишние метрики, лишние функции.
3. **Цикл Build → Measure → Learn.** Построить минимальную версию, измерить, сделать выводы, повторить.
4. **OMTM (One Metric That Matters).** В каждый момент выбирать одну главную метрику, которая важнее всего для текущей стадии.
5. **MVP.** Тестировать гипотезы минимальным рабочим продуктом.
6. **Постоянное улучшение.** Накапливать знания и корректировать курс итерациями.

## Staged framework (по стадиям роста)

- **Empathy:** понять проблему клиента — метрики: интервью, решение «было/не было», problem understanding.
- **Stickiness:** удержание — метрики: engagement, Daily/Weekly/Monthly Active Users, retention.
- **Virality:** рост через рекомендации — метрики: viral coefficient (K-фактор), цикл виральности.
- **Revenue:** монетизация — метрики: LTV, CAC, ARPU, payback period, чёрная бухгалтерия.
- **Scale:** масштабирование — метрики: каналы продаж, MQL→SQL→customer funnel, unit economics.

## Рабочий процесс для AI-ассистента

1. **Определение стадии.** Уточни, на какой стадии находится продукт (Empathy, Stickiness, Virality, Revenue, Scale) и какая главная задача.
2. **Выбор OMTM.** Предложи кандидатов в главную метрику и обоснуй, почему именно она важна сейчас.
3. **Формулирование гипотез.** Сформулируй тестируемые гипотезы и MVP для их проверки.
4. **Дизайн эксперимента.** Спланируй A/B-тест или когортный анализ: что мерим, как, на какой выборке, сколько по времени.
5. **Интерпретация.** Помоги интерпретировать результаты: значимо ли изменение, что это значит для бизнес-модели.
6. **Отказ от vanity metrics.** Проверь, что выбранные метрики реально отражают ценность, а не самоуспокоение.

## Чек-лист качества

- [ ] Выбрана и обоснована OMTM для текущей стадии.
- [ ] Метрики are "actionable, accessible, auditable" (АБ трех A: actionable, accessible, auditable).
- [ ] Гипотезы сформулированы до эксперимента, MVP минимален.
- [ ] Эксперимент спроектирован корректно (выборка, длительность, контрольная группа).
- [ ] Результаты интерпретированы без ошибок и с учётом стадии роста.

## Готовые промпты

- «Действуй по Lean Analytics. Помоги определить, на какой стадии роста находится продукт [описание продукта], и выбери OMTM.»
- «Сформулируй тестируемые гипотезы и MVP для идеи [описание идеи] по циклу Build-Measure-Learn.»
- «Спланируй A/B-тест для [изменение фичи]: переменные, выборка, длительность и метрики успеха.»
- «Проверь метрики [перечисли метрики] на vanity: насколько они отражают реальную ценность для бизнеса?»
- «Рассчитай unit economics для [модель]: LTV, CAC, payback period, и оцени устойчивость модели.»
