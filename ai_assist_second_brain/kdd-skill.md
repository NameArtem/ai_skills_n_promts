# KDD (Knowledge Discovery in Databases)

## О методологии

**KDD** — процесс обнаружения знаний в базах данных. Это итеративная методология, ориентированная на извлечение полезных, нетривиальных и ранее неизвестных закономерностей из больших массивов данных. В отличие от CRISP-DM, KDD делает больший акцент на исследовательский характер анализа и на глубокую предобработку данных.

### Ключевые характеристики

- **Цель:** обнаружение знаний и скрытых закономерностей в данных.
- **Применение:** сложные исследовательские задачи анализа данных и Data Mining.
- **Преимущества:** подходит для сложных задач, акцент на обнаружение знаний, глубина исследования данных.
- **Недостатки:** требует значительных вычислительных и человеческих ресурсов, сложность реализации, требует эксперта по предметной области.

## Этапы KDD

Процесс делится на 5 итеративных этапов (допускается возврат на любой предыдущий этап):

### 1. Выбор данных (Selection)

- Определить цели и задачи анализа (что хотим узнать?).
- Выбрать источники данных и подмножество данных (переменные, выборки, временные окна).
- Собрать данные из БД, файлов, API или других хранилищ.

### 2. Предобработка данных (Preprocessing)

- Очистка данных: обработка пропусков (missing values), выбросов (outliers), дубликатов, некорректных значений.
- Исправление ошибок ввода, приведение типов, работа с шумом.
- Устранить несоответствия и противоречия в данных.

### 3. Преобразование данных (Transformation)

- Feature engineering: создание новых признаков.
- Нормализация/стандартизация, масштабирование.
- Редукция размерности (PCA, отбор признаков), дискретизация.
- Преобразовать данные в формат, пригодный для алгоритмов Data Mining.

### 4. Data Mining

- Выбор подходящих алгоритмов: классификация, кластеризация, регрессия, ассоциативные правила, визуализация.
- Подбор и настройка параметров моделей.
- Поиск паттернов и закономерностей в данных.

### 5. Интерпретация результатов (Interpretation / Evaluation)

- Проверка значимости и достоверности найденных паттернов.
- Интерпретация результатов совместно с экспертом предметной области.
- Визуализация и оформление выводов.
- По возможности — проверка на новых/контрольных данных.

## Роли в процессе

- **Заказчик / Эксперт предметной области:** формулирует цель, интерпретирует результаты.
- **Аналитик данных:** проводит предобработку, преобразования и Data Mining.
- **Data Engineer:** организует источники и инфраструктуру данных.
- **AI-ассистент:** помогает на каждом этапе — от формулировки гипотез до интерпретации.

## Рабочий процесс для AI-ассистента

Применяй следующий пошаговый флоу при работе с задачей в рамках KDD:

1. **Фаза 0 — Понимание задачи.** Задай уточняющие вопросы: бизнес-цель, доступные данные, ограничения, критерии успеха. Зафиксируй гипотезы.
2. **Фаза 1 — Аудит данных.** Опиши структуру данных, типы полей, качество, пропуски, распределения. Составь карту данных.
3. **Фаза 2 — Очистка.** Прогнозируй проблемы (пропуски, дубликаты, выбросы), предложи стратегии обработки и реализуй их.
4. **Фаза 3 — Преобразование.** Предложи feature engineering и редукцию размерности, обоснуй выбор.
5. **Фаза 4 — Data Mining.** Подбери 2-3 алгоритма, сравни кандидатов, настрой параметры, оцени метрики.
6. **Фаза 5 — Интерпретация.** Объясни результаты простым языком, проверь их на смысловую согласованность, оформи отчет с выводами и ограничениями.

## Чек-лист качества

- [ ] Цель анализа сформулирована и согласована со стейкхолдером.
- [ ] Каждый этап задокументирован (что и почему делали).
- [ ] Предобработка повторяема и воспроизводима (скрипты, seed).
- [ ] Выбор алгоритмов обоснован, метрики соответствуют задаче.
- [ ] Результаты интерпретированы совместно с экспертом области.
- [ ] Указаны ограничения анализа и риск переобучения.

## Готовые промпты

- «Действуй по методологии KDD: начни с этапа выбора данных. Уточни, какую доменную цель мы преследуем и какие данные доступны.»
- «Проведи предобработку данных по KDD. Составь отчёт о качестве данных: пропуски, дубликаты, выбросы, типы.»
- «Помоги выбрать алгоритмы Data Mining для задачи [описание задачи] и обоснуй метрики оценки.»
- «Интерпретируй результаты модели [описание результатов] в терминах бизнеса и перечисли ограничения анализа.»
