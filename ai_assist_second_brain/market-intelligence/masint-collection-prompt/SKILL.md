## Purpose

Измерьте физический и операционный «выхлоп» одной компании и поместите
каждый сигнал в готовую к фьюжну инвентаризацию.
Workflow: **план поиска -> цепочка поставок, объекты, операции,
сертификации -> инвентаризация сигналов -> цепочки с флагами
разграничения -> пробелы и передачи.**

## Mode

**Just Enough Mode**: только самые сильные сигналы, максимум 5 цепочек
выводов, watch items в одну строку. **Verbose Mode** — только по запросу.

Это промпт сбора: он собирает и помечает, но не выносит вердикт. Оценка
уверенности по дисциплинам принадлежит
[all-source-fusion-prompt.md](all-source-fusion-prompt.md).

## Before You Start

Задайте не более 3 вопросов:

1. Какая компания — железо, инфраструктура или чистый софт?
2. Какое решение должен обеспечить этот сбор?
3. Разрешения, таможни и реестры каких стран применимы?

Если ответа нет, продолжайте с помеченными допущениями.

## Search Plan First

Покажите **план из 3 пунктов**: источники цепочки поставок, источники
объектов/проектов для [GEOGRAPHY] (для MENA — согласно региональному
оверлею), источники операций и сертификаций. Продолжайте, если не будет
правок.

## Source + Trust Rules

Реальные, проверяемые URL с датами на каждом сигнале. Не выдумывайте
**объёмы отгрузок, таможенные записи, поданные разрешения, статусы
сертификаций, количество инцидентов или измерения времени ответа.**
Помечайте каждый сигнал: **Fact** / **Inference** / **Assumption**.
Каждая аномалия называет свою разграничивающую дисциплину — MASINT-сигнал
без пути разграничения — это тест Роршаха, а не разведка. Тонкие прогоны
валидны: для программных целей короткое чтение ёмкости операций лучше
раздутых спекуляций о цепочке поставок.
